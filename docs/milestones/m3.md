# Майлстоун M3: управляемый запуск

`M3` добавляет к `M2` управляемость запуска: статус, health, бюджет, границы
тулов и eval. Это всё ещё учебный слой, а не требование построить полноценный
production runtime.

## Что запустить

```bash
uv run kb-agent --query-fixture fixtures/queries/project_query.json --vault-root vault
uv run kb-eval --eval-fixture fixtures/evals/cases.json --vault-root vault
```

## Что открыть по `run_id`

1. `vault/outputs/<run_id>-summary.md` — первая карта запуска.
2. `artifacts/source-map/<run_id>.json` — основания ответа.
3. `artifacts/runs/<run_id>.json` — статус и `terminal_reason`.
4. `artifacts/health/<run_id>.json` — базовая проверка состояния.
5. `artifacts/tools/<run_id>.json` — какие тулы read-only, а какие пишут.
6. `artifacts/traces/<run_id>.jsonl` — события и порядок шагов.
7. `artifacts/evals/<eval_run_id>.json` — результат eval-запуска.

## Готово, когда

1. `health` имеет `status: pass`;
2. eval-отчёт имеет `status: pass`;
3. write-тулы не отмечены как `model_safe: true`;
4. один `run_id` связывает summary, answer, source-map, context, trace и health;
5. в короткой заметке по `docs/handoff-template.md` есть 2-3 строки про границы
   чтения и записи.

Полный пакет сдачи описан в `docs/final-project.md`.
